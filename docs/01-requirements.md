# 需求

题号 2，内容任务规划 Agent。使用的人是内容运营。目标是在给定主题、预算和截止时间内，整理一份可保存的活动方案草稿。

## 用户与目标

运营人员给出活动主题、预算和截止时间。Agent 检索该主题的素材，生成脚本，估算费用和耗时，并在限制内保存草稿。

成功时，对方拿到一份草稿，能看到选用的方案、引用的素材、脚本、费用分项、合计和耗时。无法完成时，对方能看到未完成原因；预算两套方案都不够时，还能看到缺口。草稿不是投放，也不能被说成已发布。

## 范围

负责：

- 按主题检索素材，脚本只引用已检索素材里的事实。
- 为 `standard` 和 `lite` 生成脚本并估价。
- 由模型根据工具返回决定下一步：继续、改选轻量方案、停止，或在看到失败后结束。
- 校验通过后保存草稿。同一主题、方案和预算再次保存时，返回已有草稿。

不负责：

- 真实投放、排期和发布。
- 改写用户给出的预算或截止时间，或在缺项时编造数字。
- 编造素材表里没有的产品事实。
- 界面、多 Agent、线上部署和生产级运行环境。

材料全部自编，费用使用模拟单位。评审克隆仓库后，应能用 `data/` 里的价目表复算 12 和 8。

## 输入与输出

入口是 `data/requests.json`。每条只有 `case_name`、`theme`、`budget`、`deadline_hours`。缺失的预算或截止时间写 `null`。`case_name` 与 `examples/<用例>/` 目录名一致。

每次运行写出三份文件：

| 文件 | 内容 |
| --- | --- |
| `input.json` | 本次请求 |
| `output.json` | 任务计划、步骤状态、工具结果、费用合计、已保存方案或未完成原因 |
| `trace.json` | 每步的工具名、参数、返回摘要、下一步动作和一句依据 |

`output.json` 的字段：

| 交付内容 | 字段 |
| --- | --- |
| 任务计划 | `task_plan` |
| 步骤状态 | `step_records[].status`，取值为 `success` 或 `failed` |
| 工具结果 | `tool_results` 中的 `ok`、`code`、`message`、`data` |
| 费用合计 | `total_cost` |
| 已保存方案 | `saved_plan`；未保存时为 `null` |
| 未完成原因 | `incomplete_reason` 与 `gap` |

未完成原因只使用 `missing_budget`、`missing_deadline`、`tool_failed`、`no_feasible_plan`、`max_steps`。

## 成功标准

- 预算 20、截止 24 小时、主题「春季上新」时，保存标准方案，合计 12，耗时 6 小时。
- 预算缺失时不保存，原因是 `missing_budget`。截止时间缺失时同样不保存，原因是 `missing_deadline`。
- 工具失败时，该步保持 `failed`，此前成功的检索和脚本保留，不把失败记成成功。
- 预算 10 时，先看到标准方案合计 12，再改选轻量方案并保存，合计 8。
- 预算 5 时两套方案都超过预算，不保存，`gap` 为最便宜合计减去预算，即 3。
- 同一主题、方案和预算再次保存，返回同一个 `draft_id`。
- 工具调用达到上限仍未保存时，`status` 为 `incomplete`，原因是 `max_steps`。
- `saved_plan.total` 等于分项之和，并等于 `total_cost`。

## 固定规则

这些规则由工具和 `data/rules.json` 执行，不由模型改写：

- 缺少预算或截止时间，禁止保存。
- 合计大于预算，或耗时大于截止时间，禁止保存。
- 脚本只能使用已经检索成功的素材事实。
- 必须先成功估价，才允许保存。
- 保存幂等键是主题、方案编号和预算。
- 工具调用达到上限时，任务标为未完成。默认上限是 `max_tool_calls`，当前为 8。`max-steps` 这条用例运行时收成 2，用来验收上限。

`failure_inject.estimate_cost_first_fail` 只作用于 `tool-failure`：该用例第一次估价失败，同一进程内的第二次估价可以恢复。当前必做路径在看到失败后停止，不在同一次运行里自动重试。
